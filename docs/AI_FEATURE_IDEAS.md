# SOL-ACT AI 기능 아이디어 — 연극영화과·예고 입시생 (OpenAI 활용)

> 다각도 브레인스토밍(5개 관점 × 6 아이디어 = 30개)을 코드베이스로 검증해 우선순위를 매긴 문서입니다. **초보자용**으로 "무엇을·왜·어떻게 시작하나"를 담았습니다. (작성 2026-07-23, 자율 진행)

---

## 0. 큰 그림 — 3가지 전략 원칙

이 앱은 이미 OpenAI 스캐폴드(`ai.py revise_interview_answer`: OpenAI→Gemini→안전폴백, JSON모드)를 갖췄고, 방금 그걸 켰습니다(AI 첨삭 동작 확인). 그래서 새 AI 기능의 **착수 비용이 이미 크게 낮습니다.** 다음 3원칙만 지키면 됩니다.

1. **"런타임 0원" 캐시** — 라이브러리(제시대사 191편)·퀴즈·평가처럼 고정된 데이터는 **배치로 1번만 AI 생성 → DB에 저장**해두면, 학생이 볼 때마다 AI를 다시 부르지 않아 **비용이 0에 수렴**합니다. (원장님 비용 민감성 정면 돌파)
2. **무키 폴백** — 모든 기능은 "키 없으면 Gemini 무료티어 → 그것도 없으면 규칙기반 기본동작"으로 설계. AI가 실패해도 앱이 안 깨집니다.
3. **대필 금지, 코칭만** — 자소서를 **대신 써주면 대학 부정행위**입니다. AI는 "빠진 요소·클리셰 경보·방향 힌트"만 주고 **학생이 직접 다시 쓰게** + **교사 최종검수**. 이 선을 UI 문구로 못박습니다.

> 배포 경로: 이 기능들은 대부분 🟢 **백엔드(Python)+프론트(JS)** 라 네이티브 재빌드 불필요(단, 새 화면은 앱 재빌드 필요). DB 컬럼/테이블 추가는 **사용자 동의 후**(무손실 우선).

## 1. ⭐ 지금 만들면 좋은 우선순위 TOP 5

임팩트 × 실현성 × 저비용 × 기존자산 재사용으로 뽑은 순위입니다.

### 1위. 대본 자동 분석 카드 (인물·주어진 상황·목표·비트) — [M]
- **대상**: 학생(공통), 교사 열람
- **문제**: 입시생 최대 페인 = "대본 해석을 혼자 못 한다". 그냥 외워서 감정만 지른다.
- **어떻게**: 대본 → AI가 스타니슬랍스키식 **인물·주어진 상황·목표·비트(beat) 카드**로 구조화 출력(JSON).
- **재사용**: `PracticeScript`가 이미 situation/emotions/direction/script를 구조화 보유(191편). `revise_interview_answer`의 JSON+폴백 패턴을 함수 하나로 복제.
- **MVP(1주)**: 뽑기(draw) 상위 20편만 배치 생성 → `PracticeScript.ai_analysis`(JSON, additive) 캐시. 뽑기 결과 화면에 "해석 카드 보기" 버튼. → **라이브러리분은 런타임 0원.**
- **왜 지금**: "방법론까지 가르치는 학원"으로 학부모에게 각인.

### 2위. AI 면접관 라이브 모의면접 (꼬리질문 자동 생성) — [M]
- **대상**: 학생 주도(공통), 교사·원장 열람
- **문제**: 지금 AI 첨삭은 "질문1→답변1→끝". 실전의 핵심인 **꼬리질문 압박**(왜? 그럼 이 경우엔?)을 못 살린다.
- **어떻게**: 멀티턴 대화. 학생 답변 → AI가 `{꼬리질문, 이유, 압박강도 1~3}` 반환. 3~4턴 후 4축 총평.
- **재사용**: 방금 만든 AI 첨삭의 자연스러운 진화. `submission.kind='interview'`가 이미 있어 완료 세션을 교사 피드백 루프에 연결. **후속 아이디어(대학별 질문·자소서 꼬투리)의 엔진** 역할.
- **MVP(1주)**: 우선 "단일 꼬리질문 1개"만(기존 엔드포인트에 `mode='followup'` 분기). 멀티턴·세션 테이블은 2주차.
- **비용통제**: 세션당 8턴 상한 + 최근 6턴만 전송(슬라이딩 윈도) + 일일 세션 캡(게임화 일일캡60 패턴).

### 3위. 약점 진단 & 오늘의 학습 처방 (데일리 코치) — [S] ⚡가장 쉬움
- **대상**: 학생(공통), 교사 반 히트맵
- **문제**: 배움(퀴즈)·연습·읽을거리가 따로 논다. "오늘 뭐부터?"에서 멈춘다.
- **어떻게**: 오답 최다 퀴즈 5문제 + 최근 7일 공백 영역 15분 + 읽을거리 1편을 홈 상단 **"오늘의 처방 3개"** 카드로.
- **재사용**: `QuizAnswer/PracticeSession/Streak/ReadingContent` 전부 존재. **후보 선정이 SQL 규칙이라 AI 없이도 동작**(폴백=정상기능). AI는 "왜 지금 이걸" 한 줄만 얹음.
- **MVP**: **AI 없이 규칙만으로 먼저 출시** → 즉시 데일리 리텐션 훅. 나중에 한 줄 코칭 추가.
- **왜 지금**: 가장 저렴 + 가장 강한 재방문(streak 유지) 효과.

### 4위. 모의테스트 자동 강평 초안 (원장 리뷰 부담 경감) — [M]
- **대상**: 원장·교사 도구, 학생 열람
- **문제**: 원장이 모의테스트 수십 명 음원·영상에 코멘트를 다 달기 벅차 피드백이 얇아진다.
- **어떻게**: 학생 최근 평가(연기력·표현력·창의성·협동심·성실도 5축 + 교사 키워드) → **강평 3~4문장 초안** 생성 → 원장이 수정·승인·발송.
- **재사용**: 방금 만든 **모의테스트(MockTest)** + `evaluation.ai_summary`(존재하나 미사용 → **첫 소비처**) + 알림 발송 루프. 오디오 분석이 아니라 "기존 평가 문장화"라 환각 낮음.
- **왜 지금**: **원장 실무 절감 = 재구매(리텐션) 핵심.** 놀던 데이터를 살림.

### 5위. 역산 준비 캘린더 (실기일에서 거꾸로 짜는 주간 플랜) — [M]
- **대상**: 학생 수신, 교사 수정·승인
- **문제**: 시험까지 8주 남았을 때 "이번 주 뭘?"이 여전히 감(感).
- **어떻게**: 가장 가까운 `ExamSchedule` D-day + 학생 약한 영역 → **이번 주 PlanItem 후보 5개** 생성 → 교사 체크·삽입.
- **재사용**: `ExamSchedule·Plan·PlanItem·PracticeSession` 전부 존재. 생성 항목이 그대로 `PlanItem.content` → 기존 완료체크·streak 적립에 편입(실행률↑). 교사 플랜 작성 10분→1분.

## 2. ⚡ Quick Wins (가장 쉽고 빠른 것)

- **약점 진단 데일리 처방(3위)** — AI 없이 SQL 규칙만으로 먼저 출시 가능.
- **면접 태도 셀프체크(필러어 리포트)** — "어…음…" 검출은 **로컬 정규식(무료)**, AI는 코칭 문장만. 무키여도 부분 동작.
- **자소서 Risk checker(클리셰·과장 경보)** — 자소서 첨삭 호출에 병합하면 추가비용 ~0. 감점방지라 학부모 소구력 큼.
- **연습일지→다음 연습 처방** — 일지 저장 시 1회만 호출(트리거 기반이라 스팸 불가), streak 서사와 결합.

## 3. 🎯 Bigger Bets (크지만 차별화)

- **상대역 AI (2인 대사 실시간)** — 라이브러리 2인대사 53편으로 "집에서 페어 연습". '정본 모드'는 AI 0원(TTS 재생), '즉흥 응대'만 호출. 프론트 공수 큼(M~L).
- **멘탈코치 대화 (슬럼프·불안 케어)** — 학부모 최대 걱정 정면 대응 → 재등록·구전. `chat` 인프라 재사용. 단 **비용·안전(위기신호 정규식 선필터·상담 안내) 설계 필수**.
- **지원전략 브리핑 + 자소서 코치 계열** — 유료화 명분 최고이나 `User`에 지원정보 필드가 없어 **신규 `student_profile` 테이블 전제(effort L)**.
- **즉흥/상황면접 시뮬레이터** — 상황지문 100개 배치생성→랜덤(런타임 0원), 코칭만 실시간. "즉흥은 재능" 통념 깨는 경쟁앱 부재 기능.
- **대학별·예고별 예상질문 생성기** — `InterviewQuestion`에 school_tag 컬럼 추가, "원장만 생성·학생 무료열람"(런타임 0원). 2위 모의면접 시드로 시너지.

## 5. ⚠️ 반드시 지킬 주의사항

| 영역 | 주의점 |
|---|---|
| **비용/활성화** | `.env`에 OPENAI/GEMINI 키 + 사용자 백엔드 재시작으로만 켜짐. 무키 폴백·정적데이터 배치캐시로 비용 0에 수렴. |
| **윤리(대필=부정)** | 자소서는 **완성문장 통째 생성 금지** → 빠진요소·방향힌트만 + "본인이 다시쓰기" 강제 + 교사 검수. 예고 생기부는 학교가 작성주체라 **셀프체크·예상질문으로만 한정**. |
| **환각/정확도** | 전형정보·학교성향·사실(연혁·교수)을 AI가 단정 금지. **원장이 검수한 로컬 전형카드 JSON**을 근거로 주입, "사실 단정 금지·방향성만" 시스템프롬프트에 명시. |
| **개인정보** | 자소서·생기부·멘탈 대화는 미성년 민감정보 → 외부LLM 전송 전 동의·최소전송(요약만)·보관정책. 멘탈코치는 위기신호 시 상담 안내. **개인정보방침 갱신 필요.** |
| **데이터 부채** | 지원전략/자소서/꼬투리 계열은 `student_profile`(지원학교·자소서) 신규테이블 전제 → effort 낮게 잡지 말 것. 반면 대본분석·모의면접·데일리처방·모의강평·역산캘린더는 **기존 테이블 그대로** 써 재사용도 진짜 높음. |
| **DB 동의** | additive 컬럼·신규테이블은 **사용자 동의 후**(무손실). Postgres JSON 필터는 `cast(col, Text).like`. |
