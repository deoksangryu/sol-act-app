# SOL-ACT 모바일 v2 재설계서

> 대상 스택: `mobile/` RN 앱(Expo SDK54) + `backend/app/`(FastAPI+Postgres). 근거 문서: `sol-prototype-v1.html`, `sol-app-기능정의-및-설계의도서.md`.
> **배포 경로 분류**: v2 구현은 두 갈래다. (1) 🔴 **네이티브(RN 앱)** — `mobile/`의 화면·탭바·토큰·플레이어 확장·오디오 녹음/백그라운드 권한은 App Store/APK 재빌드 대상. (2) 🟢 **백엔드(Python)** — 게이미피케이션 코어·통합 인박스·콘텐츠·대시보드는 로컬 서버+ngrok 경로, 앱 재빌드 무관. 신규 DB 모델 추가 시 마이그레이션은 **사용자 동의 후**(데이터 무손실 최우선).
>
> ⚠️ **최상위 제약 — 데이터 무손실 & 기존 사용자 무영향**: 현재 DB는 **실사용 데이터**(users 39·classes 9·**portfolios 868**·attendances 528·music 526·lessons 484·journals 297·diet 189·notifications 11,633…). v2는 **additive(기존 데이터 그대로 + 새 테이블만 추가)**로 설계해 **기존 웹앱(sol-manager.com)·기존 RN 사용자 누구도 영향 없음**. 상세·매핑·절차는 **§10**.

## 1. 개요

v2는 "옛 웹앱을 미러링한 6탭 공용 IA"(수업·계획·영상·제시대사·식단·음악)를 **역할별 전용 IA + 게이미피케이션된 제출→피드백→푸시 루프**로 재정렬한다. 학생은 5탭(중앙 제출 FAB), 선생님은 3탭(비우는 인박스), 원장은 3탭(예외만 보는 대시보드)로 갈라지고, 모든 완료 행동에 즉시 `+N 👏`가 터지며, 학생이 제출하면 반드시 강사 인박스에 꽂히고 피드백이 학생 홈 배너로 되돌아온다. 중요한 것은 이것이 **재작성이 아니라 재조립+확장**이라는 점 — RN 하부(api/ws/auth/게이트/upload/플레이어/디자인킷)는 100% 재사용하고, 제출→피드백 스레드 4벌(영상/식단/일지/제시대사)은 로직을 그대로 옮겨 역할 탭에 재배치하며, 실제 신규는 게이미피케이션·통합 인박스·원장 대시보드·연습 플레이어 확장뿐이다.

**핵심 4원칙** (모든 설계 결정의 상위 헌법):
- **즉시성 > 보상 크기** — 완료 즉시 화면에서 무언가 터진다(+N👏 + 햅틱 15ms). 지연·일괄정산·"나중에 확인" 금지.
- **비교는 과거의 나만** — 학생 간 랭킹·서열·백분위 일절 금지. 성장은 "지난달의 나 대비 +2시간 10분"으로만.
- **학생 보호** — 보상이 채찍이 되지 않게 반대로 설계. 체중·식단 절대 비공개, 스트릭 끊김 비난 금지, 슬럼프는 강사에게만 조용히.
- **강사 UX** — 인박스는 비우는 화면. 강사 처리속도(리드타임) = 제품 품질이자 원장 핵심 지표. 3분 내 수업일지, STT 초안, 빠른 코멘트 템플릿.

## 2. 새 정보구조(IA)

### 2.1 공통 셸
- **역할 결정**: `user.role`(student/teacher/director)로 탭바 세트 확정. 첫 화면 = {학생: 홈, 선생님: 인박스, 원장: 현황}.
- **게이트 유지**: `RootNavigator.tsx`의 반배정 게이트 100% 유지, 그 아래 `MainStack`만 교체.
- **전역**: 토스트(하단 2.2초), 전체화면 딤 모달(뱃지/피드백 연출), 스크롤 top 리셋. WS(`ws.useWebSocketConnection`) 인증 트리 1회 연결 유지.

### 2.2 역할별 탭맵

| 역할 | 탭 구성 | 스택 오버레이 |
|---|---|---|
| **학생 (5탭, 중앙 FAB)** | `홈 · 연습 · [🎙️ 제출 FAB] · 배움 · MY` | 피드백 모달, 뱃지 모달, 교환소 |
| **선생님 (3탭)** | `인박스(미처리 배지) · 수업일지 · 학생` | 피드백 작성(t-review) |
| **원장 (3탭)** | `현황 · 일정 · 학생` | 학생 종합뷰(A2), 콘텐츠·교환소 관리(A3) |

중앙 제출 FAB = 52px 원·파란 배경·흰 4px 보더·`-26px` 돌출·글로우. 인박스 탭엔 실시간 빨간 카운트 배지.

### 2.3 화면 전이도 (크로스-롤 루프 = 제품의 심장)

```
[학생] 홈 ──"오늘 미션"──> 제출(중앙 FAB) ──submit──┐
                                                   ▼
        ┌──────── 강사 인박스 카운트 +1, 🆕 prepend ────────┐
        │                                                   │
[선생님] 인박스 ──> t-review ──피드백 전송──> 항목 제거·카운트-1 │
        │                    │ 학생 홈 배너 on              │
        │                    ▼                              │
        │        리드타임 확정 → 원장 현황(A1) 집계 ◀───────┘
        ▼
[학생] 홈 재방문 → 파란 피드백 배너 → 탭 → 피드백 모달
```

이 3단계가 "제출하면 반드시 답이 온다"(F3)를 UI로 보증. `services/ws.ts`의 `new_notification`/`data_changed`가 배너·카운트 실시간 갱신.

## 9. 착수 순서 제안

원칙: (1) Expo Go에서 백엔드 없이 검증 가능한 것 우선, (2) 스키마는 루프 최소만 먼저, (3) 시각 델타는 값 교체라 저비용.

1. **토큰 갱신 먼저**(색·라운드22·Pretendard) — kit 자동 반영, Expo Go 즉시 확인. 무백엔드·고가시성.
2. **IA 셸**(TabNavigator 역할 분기 + 중앙 FAB + MainStack) — 목데이터로 3역할 골격 검증.
3. **백엔드 스키마 코어**(ledger·streak·통합인박스·리드타임·PracticeSession·ExamSchedule) — **동의 후 마이그레이션**. 프론트 셸과 병렬.
4. **kit 게이미피케이션 컴포넌트**(ClapPop·Hero·TimerCard·BadgeGrid·모달) — 목데이터로 연출부터.
5. **루프 배선**(제출→인박스→t-review→배너, WS) — 3+2 위에 upload/ws 재사용. 오디오 녹음만 신규.
6. **원장 최소 대시보드**(/stats 확장 소비) — 루프 데이터 소비하므로 5 이후.
7. v2 콘텐츠/교환소/플레이어(백그라운드·락스크린은 🔴 네이티브 → 별도 빌드 사이클).

**순서 요약**: 토큰(즉시) → IA 셸(목) → 백엔드 코어(동의 후) → 게이미피케이션 연출 → 루프 배선 → 대시보드. 1·2·4는 Expo Go에서 백엔드 없이 검증 가능 → 최우선 병렬.

## 10. 데이터 호환성 & 마이그레이션 안전 (최상위 제약)

> 현재 DB는 실사용 데이터다(users 39·classes 9·class_students 27·**portfolios 868**+videos 133+comments 81·attendances 528·music_tracks 526·lessons 484·lesson_journals 297·diet_logs 189·weight_logs 23·assignments 92·practice_scripts 1,203·notifications 11,633·invite_codes 51·device_tokens 28·chat 29·questions/answers 9·notices 3·praise_stickers 3·auditions 1·plans 1). **이 전부를 그대로 쓰고, 기존 웹앱·기존 RN 사용자 누구도 문제 없어야 한다.** v2는 이를 위해 철저히 **additive(더하기만)** 로 간다.

### 10.1 3대 안전 규칙
1. **기존 테이블 파괴 금지** — drop·rename·타입변경·행삭제 **절대 없음**. 확장은 **nullable/default 컬럼 추가**만(예: `*_comments.first_feedback_at`, `users.last_active`). 기존 868 포트폴리오·528 출석 등은 손대지 않음.
2. **새 기능 = 새 테이블 + 새 엔드포인트** — 게임화·콘텐츠·일정·대시보드는 전부 **신규 테이블**(PointLedger·Streak·Badge·PracticeSession·ExamSchedule·Quiz·Reading·Media·Interview·RoutineTemplate·Exchange…). 기존 스키마와 무관.
3. **기존 엔드포인트 계약 유지 = 이중 앱 호환** — 프로덕션 웹앱(sol-manager.com)이 **같은 백엔드**를 쓰므로, 기존 API 응답 모양은 그대로 두고 **선택(optional) 필드만 추가**. → **기존 웹앱·기존 RN 앱 둘 다 계속 동작**.

### 10.2 기존 데이터 → v2 어디서 쓰이나 (하나도 안 버림)

| 기존 데이터(행수) | v2에서 쓰이는 곳 | 처리 |

| portfolios 868 · videos 133 · comments 81 | 제출 영상·통합 인박스·피드백·MY·제시대사 연기영상 | **그대로**(리드타임용 nullable 컬럼만 추가 가능) |
| attendances 528 | 커튼콜(출석)·원장 현황 | **그대로**(커튼콜 신호원) |
| lessons 484 · lesson_journals 297 · comments | 선생님 수업일지·학생 "선생님의 한 마디" 타임라인 | **그대로** |

→ **모든 기존 테이블이 v2 화면에 매핑됨. 고아(버려지는) 데이터 없음.**

### 10.3 마이그레이션 절차 (데이터 무손실)
1. 마이그레이션 전 **`pg_dump` 전체 백업**(필수).
2. **additive 마이그레이션만** — 새 테이블 생성 + 기존 테이블에 nullable/default 컬럼 추가. `DROP`/`ALTER TYPE`/`DELETE`/`RENAME` 금지.
3. **사용자 동의 후, 사용자가 직접 실행**(백엔드/DB는 사용자가 운영).
4. 가능하면 **DB 사본에서 먼저 검증** 후 본DB 적용.
5. **롤백** = 새로 만든 테이블 `DROP`만으로 원복(기존 데이터 완전 무영향).

### 10.4 소급 적용(박수·커튼콜) — 선택이며 비파괴
- 기존 868 제출·528 출석에 박수/스트릭을 **소급 지급할지는 선택**. 지급하더라도 **새 ledger 테이블에 INSERT만** 하고 기존 테이블은 불변.
- **기본값**: v2 카운터는 0부터 시작(깔끔), 또는 1회성 **비파괴 backfill 스크립트**(읽기=기존, 쓰기=새 테이블).

### 10.5 전환 기간 운영
- 백엔드가 **기존 웹앱 + 기존 RN(6탭) + 새 RN(v2)** 모두를 동시에 받아도 문제없도록, 새 엔드포인트는 추가만 하고 기존 것은 유지. 세 클라이언트가 공존 가능.
- 새 RN 앱 배포는 스토어/APK 재빌드 필요(🔴)지만, **기존 사용자는 옛 앱을 계속 쓰다가 자연스럽게 새 앱으로 이동** — 서버 데이터는 하나로 이어짐.
